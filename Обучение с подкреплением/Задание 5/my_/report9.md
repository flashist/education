# Задание 9: Реализация ограничения ALISP

## Постановка задачи

Реализовать ограничение ALISP: запрет на выполнение действия `open_door` до получения ключа. Показать, как программное ограничение порядка действий улучшает результат по сравнению с наивным (неограниченным) подходом.

## Среда

GridWorld 5×5 (`KeyDoorGrid`):

| Объект | Позиция |
|--------|---------|
| Старт агента | (4, 0) — нижний левый угол |
| Ключ | (0, 0) — верхний левый угол |
| Дверь | (4, 4) — нижний правый угол |

Награды: −1 за каждый шаг, +50 за открытие двери с ключом.

## Реализация

### Подход 1: Наивный (без ограничения)

Агент идёт к двери первым делом. Дверь не открывается (нет ключа). Затем агент вынужден идти за ключом и возвращаться к двери — лишний крюк через всё поле.

### Подход 2: ALISP-ограничение

Класс `SafeKeyDoorPolicy` реализует программный каркас поведения:

```python
class SafeKeyDoorPolicy:
    def choose_action(self, state):
        _, _, has_key = state
        if not has_key:
            return 'go_to_key'   # open_door запрещён
        return 'go_to_door'
```

Ограничение встроено в логику выбора высокоуровневого действия: пока `has_key == False`, переход к двери недопустим. Агент обязан сначала получить ключ.

## Результаты

```
Наивный:  шагов=20, награда=31
ALISP:    шагов=12, награда=39
ALISP сэкономил 8 лишних шагов
```

## Интерпретация результатов

ALISP-ограничение сократило маршрут с 20 до 12 шагов (+8 к суммарной награде), потому что исключило бессмысленный визит к двери без ключа. Агент больше не тратит ресурс на заведомо неуспешное действие.

Ключевой вывод: предметное знание («нельзя открыть дверь без ключа»), встроенное в программный каркас, сужает пространство допустимых сценариев и устраняет целый класс ошибочных траекторий ещё до начала поиска.
